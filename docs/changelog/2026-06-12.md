# Changelog

## 2026-06-12

### Async logger refactoring

Replaced synchronous file writes with an asynchronous queue-based design:

- All public API methods (`debug`, `info`, `warn`, `error`) only enqueue a
  `LogEntry` onto a lock-free `AsyncQueue` — no file I/O in the caller thread
- A dedicated writer thread (`"wifiman-log"`) consumes the queue with
  `timeout_pop(100ms)` for burst batching
- Rotation is performed atomically inside the writer thread after each batch
- `shutdown()` sets an atomic stop flag, pushes a sentinel, then joins the
  writer thread — guarantees all queued entries are flushed before exit
- Queue uses `g_async_queue_new_full` with a destroy function as a safety net
  for any entries remaining on destruction

Memory footprint verified: all allocation/free pairs are complete across every
code path (LogEntry g_slice_new/g_slice_free, g_strdup/g_free, AsyncQueue
ref/unref, thread join). No leaks in the writer loop or shutdown sequence.

### SignalIcon — Cairo-drawn Wi-Fi arcs (icon-theme independent)

Replaced `Gtk.Image` in `WifiNetworkRow` with a Cairo `SignalIcon` widget
(`src/widgets/SignalIcon.vala`) that draws Wi-Fi signal arcs directly. The
icon theme (Papirus-Dark) maps all `network-wireless-signal-*-symbolic`
names to the same fallback icon, making all signal levels look identical with
`Gtk.Image`. Cairo drawing bypasses the icon theme entirely.

- New `SignalIcon : Gtk.DrawingArea` with `strength` property (0–100)
- Draws 4 concentric arcs (radii 4, 8, 12, 16) centered at bottom-center,
  sweeping 225°→315° to form the classic curved Wi-Fi fan shape
- Uses `Gtk.StyleContext.get_color()` for CSS-aware foreground color
- Unfilled bars rendered at 20% opacity
- Rounded line caps via `Cairo.LineCap.ROUND`
- Respects `.signal-icon` CSS class for opacity overrides and hero styling

### WifiNetworkRow — property binding instead of manual signal handler

Replaced the `notify["strength"]` manual signal connection with a
`GLib.Binding` using `bind_property()`:

- Before: `strength_id = network.notify["strength"].connect(() => update_signal());`
  with `SignalHandler.disconnect()` in `disconnect_network()`
- After: `signal_binding = network.bind_property("strength", signal_icon, "strength",
  BindingFlags.SYNC_CREATE, null, null);` — no transform needed since both
  ends are `int`, cleaned up via `signal_binding.unbind()`

Also captured all previously-unsaved signal handler IDs (`access-point-count`,
`bitrate-mbps`, `scan-age-text`, `signal-dbm-text`, `ip-address`, `gateway`,
`dns-summary`, `warning-text`, `health-text`) as `ulong` fields and added
proper disconnection in `disconnect_network()`. Previously these 9 connections
leaked new handlers on every `set_item()` call.

### Bitrate fix — use AP max_bitrate instead of device current bitrate

Added `max_bitrate_kbps` field to `WifiNetwork`, populated from
`ap.get_max_bitrate()` in `update_from_ap()`. `update_runtime_details()` now
prefers the AP's advertised max bitrate and falls back to `device.get_bitrate()`
only as a last resort. This fixes the 520 Mbps cap that occurred when
mac80211/kernel driver limited the device PHY rate.

### Logger lazy formatting (performance)

Added `debug_on` flag that mirrors the `--debug` CLI flag. `Logger.debug()`
and `Logger.info()` now gate on `debug_on` before any string formatting
or GLib calls. When `--debug` is not passed, these are true no-ops — no
va_list traversal, no printf allocation, no GLib function call.

Previously `Logger.debug()` would always format its format string and
call `GLib.debug()` even with `--debug` off, because the `enabled` flag
was unconditionally set to `true` by `init()`.

### NetworkManagerService signal cleanup

Captured the previously-leaked `client.notify["connectivity"]` handler ID
in `connectivity_notify_id` and added it to `disconnect_signals()`.
Without this, every signal handler connected after a reconnect cycle
leaked a closure and kept the old client alive.

### Reference cycle fix in WifiNetworkRow

Changed the `network` field from owned to `unowned`:

- Old: `private WifiNetwork? network;`
- New: `private unowned WifiNetwork? network;`

On each `render_networks()` call, old rows were removed from the UI but
never finalized due to a reference cycle: `WifiNetwork → (signal closure)
→ WifiNetworkRow` coupled with `WifiNetworkRow → (field) → WifiNetwork`.
With `unowned`, the row no longer keeps the network alive. When the
network is removed from `networks_by_ssid` during rebuild, it's finalized,
which disconnects signal handlers, which drops the closure's ref to the
row, which finalizes the row. No orphaned objects leak across scan cycles.

### Debug logging for AP discovery

Added per-AP discovery logging in `add_or_update_access_point()` showing ssid,
strength, and max_bitrate for both new APs and updates.

### Signal icon vertical centering

Adjusted the Cairo arc center in `SignalIcon` from `cy = height` to
`cy = height - 3` so the visual center of the drawn arcs aligns with the
widget center, matching the badge text baseline.

### Cleanup — redundant `update_signal()` removed

The `update_signal()` method in `WifiNetworkRow` manually set
`signal_icon.strength = network.strength` during `update_all()`, but this
was immediately overwritten by the `GLib.Binding(SYNC_CREATE)` created on
the next line. Removed the method and its call — saves one `queue_draw()`
per row on startup.

### Cleanup — dead HEADER branch removed

`WifiNetworkRow.set_item()` had a branch for `WifiListItemKind.HEADER` that
showed a section label. This branch was unreachable — all HEADER items route
to `MainWindow.build_section_row()` which creates a plain `Gtk.ListBoxRow`,
never a `WifiNetworkRow`. Removed `section_label` field, constructor code,
HEADER branch, and related references.

### Cleanup — dead signal handlers removed

Removed signal connections for `security`, `frequency`, and
`access-point-count` from `WifiNetworkRow.set_item()`. These properties are
set once during AP discovery and never change, making their notify handlers
dead code that fires zero times in practice.

### Cleanup — redundant `update_metrics()` call removed

`update_security()` called `update_metrics()` and set
`metrics_box.visible = network.metrics_text.length > 0`. But `update_metrics()`
already sets `metrics_box.visible` based on per-label visibility, and
`update_all()` calls `update_metrics()` right after `update_security()`.
Removed both the call and the redundant `metrics_box.visible` assignment.

### Cleanup — dead utility functions removed

Removed 6 unused functions from `WifiUtils`: `signal_quality_label`,
`join_nonempty`, `connectivity_to_style`, `active_connection_reason_to_label`,
`device_state_reason_to_label`, `ssid_equal`. None were called anywhere in
the codebase.

### Cleanup — redundant `using GLib;` removed

Removed the auto-imported `using GLib;` statement from 5 files:
`Application.vala`, `MainWindow.vala`, `WifiNetwork.vala`,
`NetworkManagerService.vala`, `WifiViewModel.vala`. In Vala, the `GLib`
namespace is always auto-imported by the compiler.
