# Changelog

## 2026-06-12

### Async logger refactoring

Replaced synchronous file writes with an asynchronous queue-based design:

- All public API methods (`debug`, `info`, `warn`, `error`) only enqueue a
  `LogEntry` onto a lock-free `AsyncQueue` — no file I/O in the caller thread
- A dedicated writer thread (`"wifiman-log"`) consumes the queue with
  `timeout_pop(100ms)` for burst batching
- Rotation is performed atomically inside the writer thread after each batch
- `shutdown()` sets an atomic stop flag, pushes a sentinel, then joins the
  writer thread — guarantees all queued entries are flushed before exit
- Queue uses `g_async_queue_new_full` with a destroy function as a safety net
  for any entries remaining on destruction

Memory footprint verified: all allocation/free pairs are complete across every
code path (LogEntry g_slice_new/g_slice_free, g_strdup/g_free, AsyncQueue
ref/unref, thread join). No leaks in the writer loop or shutdown sequence.

### Reverted custom SignalIcon back to Gtk.Image

Removed `src/widgets/SignalIcon.vala` (Cairo DrawingArea with arc bars).
Restored `Gtk.Image` in `WifiNetworkRow` with themed GNOME symbolic icons:

- `network-wireless-signal-excellent-symbolic` (≥80)
- `network-wireless-signal-good-symbolic` (≥60)
- `network-wireless-signal-ok-symbolic` (≥40)
- `network-wireless-signal-weak-symbolic` (≥20)
- `network-wireless-signal-none-symbolic` (<20)

The icon mapping (`WifiUtils.signal_strength_to_icon()`) already existed in
`WifiUtils.vala` and was wired into `update_signal()` via `icon_name` property.
This follows GNOME conventions, respects icon theme, supports dark mode, high
DPI, and theme overrides automatically — without custom drawing code.

### Bitrate fix — use AP max_bitrate instead of device current bitrate

Added `max_bitrate_kbps` field to `WifiNetwork`, populated from
`ap.get_max_bitrate()` in `update_from_ap()`. `update_runtime_details()` now
prefers the AP's advertised max bitrate and falls back to `device.get_bitrate()`
only as a last resort. This fixes the 520 Mbps cap that occurred when
mac80211/kernel driver limited the device PHY rate.

### Logger lazy formatting (performance)

Added `debug_on` flag that mirrors the `--debug` CLI flag. `Logger.debug()`
and `Logger.info()` now gate on `debug_on` before any string formatting
or GLib calls. When `--debug` is not passed, these are true no-ops — no
va_list traversal, no printf allocation, no GLib function call.

Previously `Logger.debug()` would always format its format string and
call `GLib.debug()` even with `--debug` off, because the `enabled` flag
was unconditionally set to `true` by `init()`.

### NetworkManagerService signal cleanup

Captured the previously-leaked `client.notify["connectivity"]` handler ID
in `connectivity_notify_id` and added it to `disconnect_signals()`.
Without this, every signal handler connected after a reconnect cycle
leaked a closure and kept the old client alive.

### Reference cycle fix in WifiNetworkRow

Changed the `network` field from owned to `unowned`:

- Old: `private WifiNetwork? network;`
- New: `private unowned WifiNetwork? network;`

On each `render_networks()` call, old rows were removed from the UI but
never finalized due to a reference cycle: `WifiNetwork → (signal closure)
→ WifiNetworkRow` coupled with `WifiNetworkRow → (field) → WifiNetwork`.
With `unowned`, the row no longer keeps the network alive. When the
network is removed from `networks_by_ssid` during rebuild, it's finalized,
which disconnects signal handlers, which drops the closure's ref to the
row, which finalizes the row. No orphaned objects leak across scan cycles.

### Debug logging for AP discovery

Added per-AP discovery logging in `add_or_update_access_point()` showing ssid,
strength, and max_bitrate for both new APs and updates.
