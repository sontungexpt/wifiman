# Changelog

## 2026-06-13

### Root cause: GLib-GObject CRITICAL crash in `gtk_widget_set_sensitive` (Vala ABI bug)

**Symptom:** When the connect dialog is shown, the Cancel button's `gtk_widget_set_sensitive`
crashes with a GLib-GObject CRITICAL assertion failure at shutdown or during dialog
interaction. The crash stemmed from reading garbage at `_data5_->connect`.

**Root cause:** Vala compiler ABI mismatch for **local functions** used as GTK signal
handlers. `void do_connect () { }` defined inside `show_connect_dialog()` generated a
C wrapper `___lambda59___localfunc0_(gpointer self)` with only **1 parameter**.
When GTK emits a signal like `GtkButton::clicked` or `GtkPasswordEntry::activate`,
it passes **2 parameters** to the handler: `(GtkWidget* instance, gpointer user_data)`.
The Vala wrapper ignored the `instance` parameter and treated the first argument
(the widget pointer) as the `Block5Data*` closure data pointer. Since the widget's
memory layout does not match `Block5Data`, reading `_data5_->connect` and
`_data5_->dialog` returned garbage, eventually causing an invalid pointer dereference
in `gtk_widget_set_sensitive`.

Two related sub-bugs from the same local-function pattern:

1. **Missing ref-count increment:** The signal connection used raw `_data5_` as
   `user_data` without calling `block5_data_ref()`. GTK expects the user_data
   supplier to have already ref'd the data.

2. **NULL destroy notification:** No `block5_data_unref` was passed as the
   destroy-notify callback. When `g_signal_connect_data` auto-disconnects (or
   disconnects manually), the destroy notify is called — NULL means the data
   leaks if the handler outlives the data's scope.

**Fix:** Replaced `void do_connect () { ... }` with two inline lambdas:

```vala
connect.clicked.connect (() => {
    // ...
});

password_entry.activate.connect (() => {
    // ...
});
```

Lambdas generate correct 2-parameter wrappers:
- `___lambda59__gtk_button_clicked(GtkButton* _sender, gpointer self)`
- `___lambda61__gtk_password_entry_activate(GtkPasswordEntry* _sender, gpointer self)`

Lambdas also generate proper `block5_data_ref`/`block5_data_unref` destroy
notifications (same pattern used by the Cancel button's clicked handler).

### Dialog lifecycle — destroy instead of hide

Both `show_connect_dialog` and `show_network_actions` previously used
`dialog.close()` which only **hides** the window in GTK4 (the default
`close_request` handler calls `gtk_widget_set_visible(FALSE)`). Multiple
dialog opens accumulated hidden window objects.

Fixed:
- `show_connect_dialog` — `close_request` calls `dialog.destroy()` + returns
  `true`. Also clears `_connect_dialog_active` and calls
  `cancel_manual_connect()`.
- `show_network_actions` — Close button and `close_request` both call
  `dialog.destroy()`.

### `_connect_dialog_active` guard

Added `_connect_dialog_active` flag (MainWindow field 37) set to `true` when
the dialog is presented and cleared in `close_request`. The async callback
for `manager.connect_network.begin()` checks this flag before touching dialog
widgets. If the dialog was already closed, the callback returns early —
prevents crashes on destroyed widgets.

### Manual connect guard (`_manual_connecting`)

Added `_manual_connecting`, `_manual_connecting_ssid`, and
`_manual_connect_timeout_id` fields in `WifiViewModel` (lines 149–151) with a
120-second safety timeout. When `connect_network()` is called, the guard
blocks `try_auto_connect_all()` from racing against user-initiated password
flows. `cancel_manual_connect()` clears the guard, called from:
- Dialog `close_request` (user dismisses dialog)
- Manual connect timeout expiry
- `try_auto_connect_all()` when the manual network resolves as connected or failed

### SSID display — corrupted characters fix

**Root cause:** `ssid_to_string()` cast raw NM SSID bytes directly as `(string)`
without null termination, then passed the result through `make_valid()` which
replaced invalid UTF-8 with `U+FFFD` (replacement character).

**Fix:** Creates a proper null-terminated copy of the SSID bytes, validates
UTF-8, and falls back to escaped-hex representation (e.g., `\xNN`) for
non-printable or non-UTF-8 data instead of displaying replacement characters.

### `WifiViewModel.shutdown()` — timer cleanup

Added cleanup for `_manual_connect_timeout_id` and set `_started = false` in
`shutdown()`. Previously the 120s manual connect timeout could fire after
shutdown, and `_started` remained `true` allowing signal-triggered rebuilds
after shutdown.

### Connection commit for saved networks

When connecting to a saved network with a new password, `apply_secrets()` now
calls `commit_changes_async(true, null)` to persist the password to
NetworkManager. Previously the in-memory modification was never committed,
causing the next connection attempt to use the stale password.

### Logger shutdown race fix

Reordered `Logger.shutdown()`: pushes the "Session ended" sentinel entry
**before** setting the `_stopped` atomic flag. Previously `_stopped` was set
first, giving the writer thread a window to check the flag, find it set, and
exit before the sentinel was enqueued.
