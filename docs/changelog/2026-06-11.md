# Changelog

## 2026-06-11

### Hard safety guarantee — auto-disconnect prevention

Added three safety guards in `WifiViewModel` to ensure the app never automatically disconnects the active Wi-Fi connection:

- **`_started` flag**: Prevents auto-connect during initial startup. The constructor calls `rebuild()` before `_started = true`, so the first rebuild is read-only.
- **`auto_reconnect_enabled` toggle**: Public property (default `true`) that can be set to `false` at runtime to disable all auto-connect behavior entirely.
- **`has_active_wifi_connection()`**: Checks NM's active connections for any wifi in `ACTIVATED` or `ACTIVATING` state. When true, both `try_auto_connect_all()` and `try_auto_connect()` are skipped — auto-connect never runs while any connection is active.

Both `try_auto_connect_all()` (called from `rebuild()`) and `try_auto_connect()` (individual network) check all three guards before calling `service.connect_network()`.

### Live scan freshness timer

Added a 5-second periodic timer that re-computes the "Updated X seconds ago" text from the stored last-scan timestamp, so the label updates in real time instead of only during rebuilds.

### CLI toggle behavior

Added `--toggle` flag and `"toggle"` GAction for single-instance show/hide. Closing the window hides it instead of quitting, keeping background scanning alive.

### Project rename

Renamed project from `wifi-vala` to `wifiman`.

### Performance optimizations

- **Removed redundant `update_connectivity_state()` from `changed` signal**: connectivity state is already refreshed during `rebuild()` → `refresh_runtime_details()`. Eliminates a D-Bus `GetConnectivity` call on every NM signal.
- **Pre-computed `lower_ssid`**: `WifiNetwork` now caches the lowered SSID on set, avoiding a string allocation per network on every `matches_search()` call.
- **Removed duplicate `render_networks()`**: `items_changed` was calling `render_networks()` directly, but `update_state()` already calls it.
- **SSID string safety**: added `.strip()` to `ssid_to_string()` to remove null-padding bytes from NM's 32-byte SSID field.

### CSS variables and dark-mode refactor

- Added 14 `@define-color` variables at top of `style.css` (`@dark-bg`,
  `@dark-surface`, `@dark-text`, `@dark-accent`, etc.)
- All dark-mode hex values replaced with variable references
- All `rgba(r,g,b,a)` calls in dark mode converted to `alpha(@variable, a)`

### Popover structure sync

- Moved structural properties (`border-radius`, `border`, `outline`, `padding`,
  `box-shadow`) into base popover rules shared by light and dark modes
- Dark mode popover only overrides background colors and drop-shadow intensity

### Dialog close button

- Replaced `Gtk.Button` with `Gtk.Image.from_icon_name("window-close-symbolic")`
  + `Gtk.GestureClick` to eliminate button-specific padding/constraints
- Close uses `Gtk.HeaderBar.pack_end()` with `halign: END`, `valign: CENTER`
- CSS: 46×46px hit-box, `border-radius: 0 12px 0 0` (matches modal corner),
  zero padding/margin/border, transparent background, hover effect
- Added `headerbar.dialog-headerbar .end { padding:0; margin:0; min-width:0 }`
  to suppress HeaderBar's internal end-box spacing

### Dialog titlebar

- Title centered via `header.title_widget = title_label`

### Search bar

- Changed from `search_changed` to `((Gtk.Editable) search_entry).changed` to
  fire on every keystroke (bypasses GTK's internal 150ms `search-delay`)
- Search bar `border-radius`: 99px → 12px

### Documentation

- Updated `docs/architecture.md` with dialog titlebar details, close button
  styling, CSS variables, popover structure, and search signal info
