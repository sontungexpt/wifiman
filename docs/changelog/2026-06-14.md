# Changelog

## 2026-06-14

### Log namespace rewrite (was `Logger`)

Replaced `Logger` class with `Log` namespace — production-grade multi-category
logging with size-based rotation, crash handling, and category routing.

**New features:**
- Five levels: `DEBUG`, `INFO`, `WARN`, `ERROR`, `FATAL`
- Four category files: `app.log`, `wifi.log`, `security.log`, `crash.log`
  in `~/.local/state/wifiman/logs/`
- Size-based rotation: 2 MiB per file, 10 backups (configurable via
  `Log.Config`)
- Crash handler for POSIX signals (SIGSEGV, SIGABRT, SIGFPE, SIGBUS, SIGILL)
  and GLib ERROR/CRITICAL — all write synchronously to crash.log
- Thread safety via lock-free `AsyncQueue` + single writer thread
- Module-based auto-routing: `Log.info("NetworkManager", ...)` → wifi.log
- `Log.Config` class with `log_dir`, `level`, `format`, `max_file_size`,
  `max_rotated_files` defaults (2 MiB, 10)
- Both TEXT and JSON output formats

**API changes:**
- `Logger.*` → `Log.*` (69 call sites updated)
- `Logger.init(bool)` → `Log.init(Log.Config, bool verbose)`
- Added `Log.install_crash_handler()` (called after init)
- Added `Log.shutdown()` (called in `MainWindow.quit_application()`)
- Legacy cleanup: removes old `wifiman.log` / `.1` / `.2` / `.3` on init

### Memory leak fixes — signal handler cleanup in shutdown

**`NetworkManagerService.shutdown()`** — now disconnects all 8 NM.Client
signal handlers (`device_added`, `device_removed`, `connection_added/removed`,
`active_connection_added/removed`, `wireless-enabled`, `connectivity`) **and**
iterates per-device (5 handlers per device) and per-active-connection
(1 handler each) signal tracking to actually disconnect them before clearing
the hash tables. Previously the tables were just cleared without disconnecting,
causing GLib-GObject-CRITICAL at exit when libnm finalized proxy objects with
orphaned handler connections still attached.

Previously `shutdown()` was a no-op — signal callbacks could fire after the
ViewModel had been shut down.

**`WifiViewModel.shutdown()`** — now disconnects all 5 service signal
handlers (`changed`, `scan_started`, `scan_finished`, `error`,
`connection_failed`) before calling `service.shutdown()`.

Previously only timers were cleaned up; signal handlers from the ViewModel
to the service remained connected, risking callbacks into a partially-shut-down
ViewModel.

### Dead code removal

- `NetworkManagerService.apply_secrets()` — unused since the password‑bypass
  refactor (superseded by `create_connection()` with fresh `NM.SimpleConnection`)
- `Log.vwrite()` — private helper never called

### Reference cycle fix — `unowned` in `WifiNetworkRow`

Changed `private WifiNetwork? network;` to `private unowned WifiNetwork? network;`.
The 2026-06-12 changelog described this fix but it was never committed.

Without `unowned`, every `render_networks()` cycle created a reference cycle:
`WifiNetwork → (signal closure) → WifiNetworkRow` coupled with
`WifiNetworkRow → (owned field) → WifiNetwork`. Rows accumulated across
scan cycles despite being removed from the UI.

### Log performance — timestamp caching

`Log.timestamp()` now caches the formatted ISO 8601 string and only recomputes
when the millisecond changes (via `GLib.get_real_time() / 1000` key). In
burst-logging scenarios this avoids one `DateTime.now_local()` allocation and
one `printf`-format per entry.

### Crash writer fix — `fatal()` uses `GLib.message()`

`Log.fatal()` now calls `GLib.message()` instead of `GLib.critical()` before
aborting. `GLib.critical()` fires the GLib log hook, which sync-writes to
crash.log — causing every FATAL entry to be double-written (once by the
`fatal()` function's `Posix.write()`, once by the hook). Using `message()`
skips the hook, so each FATAL entry appears exactly once in crash.log.

### Dead constants removed

Removed unused constants `CRASH_BUF_SIZE` and `MAX_FILE_SIZE_DEFAULT` from
`Logger.vala`.

### WifiNetworkRow lifecycle fix — removed `disconnect_all_rows_in_container()`

**Bug:** GLib-GObject-CRITICAL "instance with invalid (NULL) class pointer"
followed by `g_signal_handler_disconnect` assertion failures during every scan
rebuild cycle.

**Root cause:** `disconnect_all_rows_in_container()` called `unlink_network()`
on each old row from `render_networks()`, which called
`SignalHandler.disconnect (network, ...)`. By the time `render_networks()` runs,
the old networks have already been finalized — `rebuild_items()` calls
`networks_by_ssid.remove_all()` then `items.splice()`, which releases the last
refs. The GBinding from `bind_property` does **not** hold a strong ref to the
source (WifiNetwork), so it cannot prevent finalization.

**Fix:**
- Removed `disconnect_all_rows_in_container()` call from `render_networks()`
- Removed `disconnect_all_rows_in_container()` static method entirely
- GLib auto-disconnects all notify signal handlers and destroys the binding
  during WifiNetwork finalization (step 3 above), so manual cleanup is
  unnecessary
- The rows are still in the list box at this point (held alive by the
  container), then properly disposed by `remove_all()` without accessing the
  dangling `network` pointer
- Updated `WifiNetworkRow.dispose()` doc-comment to reflect the new lifecycle

### Crash.log no longer created on startup

- Removed the startup banner from `install_crash_handler()` — crash.log is no
  longer written to (or created) on every launch
- Removed pre-open of `_crash_fd` in `Log.init()` — the fd is now opened
  lazily on the first `sync_write_crash()` call (first actual crash event:
  FATAL, GLib ERROR/CRITICAL, or POSIX signal)
- `sync_write_crash()` caches the opened fd so repeated writes (e.g. multiple
  ERROR/CRITICAL before abort) don't open/close on each call
- `_crash_fd` comment updated to reflect lazy-open strategy

### Connection failure tracking — auto-connect death spiral fix

**Bug:** `on_connection_failed()` had an early `if (!_manual_connecting) { return; }`
that silently ignored ALL auto-connect failures. When auto-connect used a saved
(wrong) password and failed, no state was updated, no password prompt was shown,
and auto-connect kept retrying every ~20s forever. The user saw that no network
could connect and concluded NM was broken.

**Fix:**
- `on_connection_failed()` now always records the SSID in
  `auto_connect_failures` — stops endless auto-connect retries
- `try_auto_connect_all()` skips SSIDs in `auto_connect_failures`
- Manual-connect failures still emit `connect_failed` to show a password dialog
- `connect_network()` clears the SSID from `auto_connect_failures` when the user
  explicitly tries again

### Stale `_manual_connecting` flag — stuck Idle handler fix

**Bug:** The Idle handler in `connect_network()` set `_manual_connecting = true`
after the dialog's `close_request` had already called `cancel_manual_connect()`
to clear it. This left `_manual_connecting` stuck `true` for up to 120s,
blocking the auto-connect resolution check.

**Fix:**
- Added `_connect_attempt_id` counter, incremented in `cancel_manual_connect()`
- Idle handler captures `my_attempt = ++_connect_attempt_id` before the yield;
  when it runs, it checks `my_attempt != _connect_attempt_id` — if
  `cancel_manual_connect()` was called in between (incrementing the counter),
  the Idle handler skips flag-setting entirely

### Auto-connect no longer blocked by manual flag

**Fix:** `try_auto_connect_all()` no longer returns early when
`_manual_connecting` is true. It only uses the flag to detect when the manual
network has resolved (connected or failed). Other networks can still
auto-connect even while a manual connection is in progress — the specific SSID
is already covered by `is_connecting` / `auto_connecting` per-network flags.

### Dialog close always cancels manual connect

`show_connect_dialog` close_request: removed `!connect_initiated` guard.
`cancel_manual_connect()` is now called unconditionally regardless of when the
D-Bus async return completed.

### Saved connection update — delete-first approach

`NetworkManagerService.connect_network()` for saved connections with a password:
- Delete the old saved connection **first** via `delete_async()`
- Then `add_and_activate_connection_async()` with a fresh `NM.SimpleConnection`
- Delete failure is logged but doesn't block the add+activate

This avoids both the orphaned-duplicate issue (original approach: add+activate
then delete) and the uncertainty of `commit_changes_async()` on a
`NM.RemoteConnection` (previous fix attempt).

### Rebuild batching — freeze/thaw

`rebuild_items()` in `WifiViewModel` wraps the three `notify_property()` calls
in `freeze_notify()` / `thaw_notify()` — reduces render passes from 4→2 per
rebuild (was: `items.splice()` trigger + 3 sequential `notify_property()` calls,
each firing `update_state()` → `render_networks()`).
